# ARMusicPlay 项目阶段汇报（乐器弹奏 + 手势交互）

本文用于阶段性汇报，聚焦两块核心能力：

- **乐器弹奏系统**：古琴 / 琵琶在手机端的触控弹奏（按音 / 泛音 / 推拉 / 滑音），以及 PC 端测试交互。
- **手势交互系统**：基于 **MediaPipe Unity Plugin（homuler）** 的手部关键点识别，实现自定义的“捏合=点击 UI”的手势交互，并按场景开关手机摄像头以节省资源。

---

## 1. 项目目标与演示价值

- **目标**
  - 在移动端实现“可弹奏的传统乐器交互”，强调真实演奏逻辑（按品 + 拨弦 + 推拉）。
  - 提供可展示的“手势交互”能力，用于 UI 点击/翻页等，体现 AR 交互的扩展性。

- **演示亮点**
  - 手机端：多指按品 + 另一指拨弦，支持“滑动到新弦自动触发发声”（连续扫过多根弦的演示效果）。
  - 技术演示 UI：每根弦可用滑块实时调整响度（证明系统可被精细调参与扩展）。
  - 手势场景：进入场景申请摄像头权限并开启识别；离开场景自动关闭摄像头（工程化考虑）。

## 2. 工程结构（当前目录与关键脚本）

### 2.1 乐器弹奏脚本（`Assets/Scripts/Instrument/`）

- `InstrumentInputManager.cs`
  - 输入总入口：PC 鼠标 / 手机触控（多指），负责射线检测、按品/拨弦触发、跨弦触发等。
- `GuqinController.cs`、`PipaController.cs`
  - 奏法规则层：根据输入决定空弦/按音/泛音/推拉；自动生成品位碰撞体；维护实时按品与推拉状态。
- `InstrumentString.cs`
  - 弦能力层：负责最终播放音频、音高变调、泛音倍率、持续音高更新（推拉/滑音）、视觉反馈（颜色/震动）、每弦音量。
- `InstrumentVolumePanel.cs`
  - 技术演示 UI：每根弦一个滑块，映射到 `InstrumentString.stringVolume`。

### 2.2 手势交互脚本（`Assets/Scripts/HandDecter/`）

- `HandInteractionManager.cs`
  - 场景入口：申请摄像头权限（Android），启动手势系统。
- `HandLandmarkDataCollector.cs`
  - 数据入口：订阅 MediaPipe `HandLandmarkerRunner` 事件，收集手部关键点（归一化/世界坐标）供后续使用。
- `HandGestureDetector.cs`
  - 手势识别：计算拇指尖与食指尖距离，小于阈值视为“捏合”。
- `HandUIInteraction.cs`
  - UI 交互：把“捏合中心点屏幕坐标”当作指针，对 UI 做 Raycast，并触发 Button/Toggle/IPointerClickHandler。

### 2.3 场景切换与其他

- `Assets/Scripts/SceneLoader.cs`
  - 场景切换：按钮绑定切换场景；可选联动关闭手势摄像头（离开手势场景前调用 `DisableHandCamera()`）。
- `Assets/Scripts/DisplayRatioFix.cs`
  - 解决不同手机屏幕比例造成的 UI/相机视野异常。

## 3. 乐器弹奏功能：实现方案与技术细节

### 3.1 核心设计：三层架构（输入层 / 规则层 / 能力层）

- **输入层（InstrumentInputManager）**
  - 将屏幕输入转换为 Raycast 命中（弦 Collider / 品位 Collider）。
  - 手机端多指：一指负责按品（持续写入实时按品/推拉），另一指负责拨弦（命中弦时触发发声）。
  - 支持“同一指滑到新弦也触发一次拨弦”，用于演示连续扫过多根弦时逐根发声。

- **规则层（GuqinController / PipaController）**
  - 维护 `liveFretHoldByString`（每根弦当前按品）与 `liveBendByString`（每根弦推拉半音偏移）。
  - 拨弦时按实时状态决定：
    - **散音（空弦）**：无按品 → `PluckString()`
    - **泛音**：按在“泛音点”（当前实现示例：`fretIndex==0`）→ `PluckStringHarmonic(multiplier)`
    - **按音/推拉**：按品 → `PressFret(fret)` + `PluckStringWithBend(bend)`
  - 持续发音阶段：在 `Update()` 中对 `isPlaying` 的弦实时更新音高（滑音/推拉实时变化）。

- **能力层（InstrumentString）**
  - 播放策略：
    - 有逐品采样：优先 `fretSounds[]`
    - 否则用 `openStringSound` + 12 平均律变调（\(2^{(fret+1)/12}\)）
  - 持续发音音高更新：
    - `UpdateSustainPitch(totalMultiplier)` 用于“拨弦后按品/推拉”的实时变调。
  - 视觉反馈：
    - 弦变色、缩放震动（支持视觉弦与碰撞弦分离）。
  - **每弦响度**：
    - `stringVolume`（单弦混音微调） + 控制器 `masterVolume`（整把乐器主音量）。

### 3.2 品位检测：每弦独立品位碰撞体

控制器支持自动生成“每根弦各自一排品位触发器”：

- 结构：`FretCollidersPerString/String_X_Fret_Y`（BoxCollider + `FretInfo`）
- 优势：避免“按品命中错弦”的问题，手感更稳定。

### 3.3 技术演示：每弦音量滑块面板

在 `InstrumentVolumePanel` 中提供两套面板（古琴/琵琶）：

- 每个 Slider 对应一个 `InstrumentString.stringVolume`
- 切换乐器时只同步内部状态（面板是否弹出由你自己的按钮控制）

## 3.4 关键脚本与关键方法速查（汇报用讲解稿）

这一节的目标是：你在汇报时能把“代码如何组织、为什么这么拆、调用链如何流动”说明白。

### 3.4.1 输入层：`InstrumentInputManager`（触控/鼠标 → Raycast → 触发规则层）

文件：`Assets/Scripts/Instrument/InstrumentInputManager.cs`

- **核心字段**
  - `useTouchInput` / `autoDetectPlatform`：编辑器与真机输入模式切换。
  - `inputCamera`、`raycastDistance`、`raycastLayerMask`：射线检测配置。
  - `guqinController` / `pipaController`、`activeInstrument`：当前激活乐器与路由。
  - `bendPixelsPerSemitone`：推拉灵敏度（像素位移 → 半音）。
  - `toggleInstrumentGameObjectsOnSwitch`：切换乐器时显隐对应乐器根物体。
  - `volumePanel`：可选联动音量面板（切乐器时同步 UI 内部状态）。

- **关键方法（PC）**
  - `Update()`：读取键盘切换奏法（数字键）与切乐器（Tab），并分发到鼠标/触控分支。
  - `HandleMouseInput()`：左键拨弦、右键记录按品（PC 测试用）。
  - `SendPluckEvent(ray)` / `SendFretRecordEvent(ray)`：把 Ray 路由到当前乐器控制器。

- **关键方法（手机触控）**
  - `HandleTouchInput()`：根据 `activeInstrument` 路由到古琴/琵琶多指逻辑。
  - `HandleGuqinTouchMultiFinger()` / `HandlePipaTouchMultiFinger()`
    - 先更新按品（写入控制器 `SetLiveFretHold` / `SetBendAmount`）
    - 再触发拨弦（调用控制器 `HandlePluckWithLiveFret(ray)`）
    - 支持“同一指滑到新弦就触发一次拨弦”（用于演示连续扫过多根弦逐根发声）

- **关键方法（切换乐器）**
  - `SetActiveInstrument(index)`：统一入口
    - 清理触控残留状态（按品/推拉/触点缓存）
    - `ApplyInstrumentVisibility()`：显示/隐藏乐器根物体
    - `volumePanel.OnInstrumentChanged()`：同步音量面板内部状态
  - `ActivateGuqin()` / `ActivatePipa()`：给按钮直接绑定的便捷方法

> 汇报说法：输入层只负责“把触控/鼠标变成 Ray + 状态”，不直接决定音高/奏法；奏法规则在控制器层，发声能力在弦层。

### 3.4.2 规则层：`GuqinController` / `PipaController`（解释输入为奏法）

文件：

- `Assets/Scripts/Instrument/GuqinController.cs`
- `Assets/Scripts/Instrument/PipaController.cs`

- **核心字段**
  - `InstrumentString[] strings`：弦数组（按 `stringIndex` 排序）。
  - `createFretCollidersPerString`、`fretCollidersPerString`：每弦品位碰撞体（推荐）。
  - `masterVolume`：整把乐器主音量（给 UI/调参用）。
  - `liveFretHoldByString`：手机端实时按品（每弦当前按品）。
  - `liveBendByString`：手机端实时推拉（每弦半音偏移）。

- **关键方法（手机端拨弦入口）**
  - `HandlePluckWithLiveFret(ray)`
    - Ray 命中弦后，读取该弦当前 `liveFretHoldByString`：
      - **无按品** → 散音：`ReleaseFret()` + `PluckString()`
      - **泛音区（示例：fretIndex==0）** → `PluckStringHarmonic(multiplier)`
      - **按音/推拉** → `PressFret(fret)` + `PluckStringWithBend(bend)`

- **关键方法（持续变音：滑音/推拉）**
  - `Update()`：对 `strings[i].isPlaying==true` 的弦，按“当前按品 + 当前推拉”计算总音高倍率，调用：
    - `InstrumentString.UpdateSustainPitch(totalMultiplier)`

- **关键方法（品位碰撞体）**
  - `CreateFretCollidersPerString()`：自动生成每弦每品触发器，并挂 `FretInfo(stringIndex, fretIndex)`
  - `GetFretFromHit(hit, out si, out fi)`：把 Raycast 命中解析成“第几弦第几品”

> 汇报说法：控制器层只做“规则与状态管理”，不直接操作输入系统，也不把音频细节写死在这里；它只决定调用弦层的哪一个能力函数。

### 3.4.3 能力层：`InstrumentString`（最终发声与视觉反馈）

文件：`Assets/Scripts/Instrument/InstrumentString.cs`

- **核心字段**
  - `openStringSound` / `fretSounds[]`：音频资源（空弦/逐品）。
  - `usePitchShifting` / `preferCustomFretSounds`：音频选择策略。
  - `stringVolume` / `baseVolume`：每弦音量（技术演示滑块直接改这里）。
  - `visualStringObject`：视觉弦（与碰撞弦分离）。

- **关键方法**
  - `PressFret(fretIndex)` / `ReleaseFret()`：设置当前按品状态（影响音高计算）。
  - `PluckString()`：空弦拨弦入口（内部转 `PluckStringWithBend(0)`）。
  - `PluckStringWithBend(bendSemitones)`：按品/推拉拨弦入口
    - 选择 clip：逐品采样优先，否则空弦 clip + 变调倍率
    - 设置 `audioSource.pitch` 并 `Play()`
    - `audioSource.volume` 由 `CalculateCurrentVolume()` 统一计算（包含 `stringVolume` + 控制器 `masterVolume`）
  - `PluckStringHarmonic(multiplier)`：泛音播放（用倍率直接改变 pitch）
  - `UpdateSustainPitch(totalMultiplier)`：持续发音期间实时更新音高（滑音/推拉）

> 汇报说法：弦层是“能力组件”，它不关心输入来自鼠标/触控/手势，只要被调用，就会以统一规则播放音频并做视觉反馈。

### 3.4.4 技术演示 UI：`InstrumentVolumePanel`（每弦响度）

文件：`Assets/Scripts/Instrument/InstrumentVolumePanel.cs`

- **关键方法**
  - `ShowGuqinPanel()` / `ShowPipaPanel()`：显示对应面板并刷新滑块值
  - `OnInstrumentChanged(index)`：切换乐器时同步内部状态（不强制弹面板）
  - `SyncGuqinFromStrings()` / `SyncPipaFromStrings()`：把当前 `stringVolume` 同步回 UI

## 4. 手势交互：插件选择与自定义实现

### 4.1 插件选择：MediaPipe Unity Plugin（homuler）

- **选择原因**
  - MediaPipe 提供稳定的手部关键点检测（21 点），适合做自定义手势（捏合、张开、滑动等）。
  - Unity 侧可通过 `HandLandmarkerRunner` 获取结果，和 UI/交互逻辑解耦。

### 4.2 自定义手势：捏合（Pinch）= 点击 UI

实现路径：

1. **数据采集（HandLandmarkDataCollector）**
   - 订阅 `HandLandmarkerRunner.OnHandLandmarkResult`
   - 将每只手 21 个关键点写入 `allHandsLandmarks`（归一化坐标）等结构

2. **手势识别（HandGestureDetector）**
   - 取拇指尖（索引 4）与食指尖（索引 8）
   - 计算距离，小于阈值 `pinchDistanceThreshold` 判定为捏合
   - 计算捏合中心点屏幕坐标 `pinchScreenPosition`

3. **UI 交互（HandUIInteraction）**
   - 用 `EventSystem.RaycastAll` 对屏幕坐标做 UI 射线
   - 优先命中 Button/Toggle/任意 `IPointerClickHandler`
   - 支持冷却 `interactionCooldown` 防抖
   - 射线未命中时用“距离最近按钮”做备用命中（演示更稳）

### 4.3 按场景开关摄像头（工程化）

你当前是“手势交互场景”与“乐器弹奏场景”分离，因此采用：

- **进入手势场景**：
  - `HandInteractionManager` 申请摄像头权限（Android），通过后启动手势 Runner
- **离开手势场景**：
  - `SceneLoader` 可选引用 `HandInteractionManager`，切场景前调用 `DisableHandCamera()` 关闭摄像头（节能、避免后台占用）

## 4.4 手势交互关键脚本与关键方法速查（汇报用讲解稿）

### 4.4.1 场景入口：`HandInteractionManager`（权限 + 启动/关闭）

文件：`Assets/Scripts/HandDecter/HandInteractionManager.cs`

- **核心字段**
  - `startCameraOnStart`：进入手势场景是否自动启动。
  - `dataCollector` / `gestureDetector` / `uiInteraction`：手势链路三段引用。

- **关键方法**
  - `Start()`：自动查找组件后，若 `startCameraOnStart==true` 则启动协程初始化摄像头。
  - `InitCameraRoutine()`：
    - Android：`Permission.RequestUserPermission(Permission.Camera)` 请求权限
    - Unity：`Application.RequestUserAuthorization(UserAuthorization.WebCam)`（兼容）
    - 通过后调用：`dataCollector.StartCamera()`
  - `DisableHandCamera()`：离开场景时关闭（调用 `dataCollector.StopCamera()`）

> 汇报说法：手势系统按场景启停，避免在弹奏场景浪费电量/占用摄像头；权限申请也集中在这一层做。

### 4.4.2 数据入口：`HandLandmarkDataCollector`（订阅 MediaPipe 结果）

文件：`Assets/Scripts/HandDecter/HandLandmarkDataCollector.cs`

- **关键字段**
  - `handLandmarkerRunner`：MediaPipe 提供的 `HandLandmarkerRunner`
  - `allHandsLandmarks` / `normalizedLandmarks`：关键点缓存

- **关键方法**
  - `Start()`：订阅 `handLandmarkerRunner.OnHandLandmarkResult`
  - `StartCamera()`：
    - 检查 `WebCamTexture.devices`（用于确认设备是否存在）
    - 通过后调用 `handLandmarkerRunner.Play()`（启动 Runner）
  - `OnHandLandmarkResultReceived(result)`：回调里缓存最新结果
  - `Update()` → `ProcessLatestResult()`：把结果转为更易用的数据结构（归一化/世界坐标）

### 4.4.3 手势识别：`HandGestureDetector`（捏合判定）

文件：`Assets/Scripts/HandDecter/HandGestureDetector.cs`

- **关键方法**
  - `Update()`：遍历检测到的手
  - `IsHandPinching(handIndex)`：计算拇指尖(4)与食指尖(8)距离，小于 `pinchDistanceThreshold` 视为捏合
  - 输出 `pinchHands[]`：给 UI 层使用（包含屏幕坐标）

### 4.4.4 UI 交互：`HandUIInteraction`（把捏合当点击）

文件：`Assets/Scripts/HandDecter/HandUIInteraction.cs`

- **关键方法**
  - `Update()`：无捏合则清空状态；有捏合则 `CheckPinchInteraction()`
  - `RaycastUI(screenPos)`：用 `EventSystem.RaycastAll` 获取 UI 命中
  - `TriggerClick(target, screenPos)`：触发 Button/Toggle/PointerClick
  - `interactionCooldown`：冷却防抖

> 汇报说法：我们没有改 MediaPipe 的模型，只消费它产出的 21 点关键点；手势定义与 UI 交互完全由我们自定义实现，便于后续扩展更多手势。

## 5. 移动端打包注意事项（MediaPipe 摄像头与原生库）

- **摄像头权限**
  - Android 需要在运行时申请 Camera 权限（项目内已在 `HandInteractionManager` 中处理）。

- **原生库依赖**
  - 若真机日志出现类似：
    - `libc++_shared.so not found`（被 `libopencv_java4.so` 依赖）
  - 需要将对应 ABI 的 `libc++_shared.so` 打包进 APK。
  - 若 `Assets/Plugins/Android` 不存在，可以**自行创建目录**：
    - `Assets/Plugins/Android/arm64-v8a/libc++_shared.so`
  - 重新打包后再验证摄像头 Source 是否正常列出。

## 6. 可扩展方向（后续工作建议）

- **弹奏扩展**
  - 增加更多奏法（轮指、颤音、闷音等）：优先扩展 Controller 的规则，再扩展 `InstrumentString` 的能力方法。

- **手势扩展**

## 7. 结论

本阶段已经完成：

- 在手机端实现古琴/琵琶的核心弹奏交互（按品、泛音、推拉、滑音、跨弦触发）。
- 通过滑块面板提供可演示的“每弦响度可控”能力。
- 基于 MediaPipe 实现“捏合=点击 UI”的自定义手势交互，并按场景启停摄像头，具备工程可落地性。

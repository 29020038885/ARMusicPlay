# 协作开发指南（如何新增功能 / 调整现有脚本）

本文面向后续继续迭代本项目的同学，目标是：**你想加新功能时知道从哪里接入**，**你想改旧功能时知道改哪一段脚本最安全**，并能快速自查“为什么没反应/没声音/按品不生效”等问题。

> 适用范围：`Assets/Scripts/` 下的乐器交互系统（古琴/琵琶）、手势 UI 点击、场景切换、显示比例修正。  
> 推荐先读：[场景与组件说明](./场景与组件说明.md)（模型/碰撞体/场景物体怎么摆）。

---

## 0. 快速总览（你需要记住的 4 个入口）

- **输入入口（鼠标/触控）**：`InstrumentInputManager`
  - 负责把屏幕输入转换为射线、区分 PC/手机、管理多指、决定“什么时候算按品/什么时候算拨弦/什么时候算扫弦”。
- **乐器入口（奏法规则）**：`GuqinController` / `PipaController`
  - 负责“当前奏法如何解释输入”、品位碰撞体创建、以及把结果下发到具体弦（`InstrumentString`）。
- **发声+视觉入口（单根弦）**：`InstrumentString`
  - 负责最终播放音频、音高变调、泛音倍率、推拉实时改音高、以及弦震动/变色反馈。
- **手势 UI 点击入口（捏合点击 UI）**：`HandInteractionManager` → `HandGestureDetector` → `HandUIInteraction`
  - 完全独立于乐器弹奏逻辑，只做“捏合=点击 UI”。

额外两类“基础设施”：

- **场景切换**：`SceneLoader`
- **分辨率/比例修正**：`DisplayRatioFix`

## 1. 系统工作流（从输入到发声的链路）

### 1.1 PC（鼠标）链路

- `InstrumentInputManager.Update()`
  - 左键：`SendPluckEvent(ray)` → 当前乐器 `HandlePluck(ray)`
  - 右键：`SendFretRecordEvent(ray)` → 当前乐器 `HandleFretRecord(ray)`（只记录按品，不发声）
  - 数字键：切换奏法（古琴 `1~4`，琵琶 `1~5`）
  - `Tab`：切换激活乐器（古琴/琵琶）

### 1.2 手机（触控，多指）链路（古琴/琵琶弹奏）

触控逻辑的关键原则是：**先更新“实时按品/推拉状态”，再触发拨弦**，这样符合真实奏法（先按/推拉再拨弦，或拨弦后再推拉时音高也会实时变）。

- 古琴：`InstrumentInputManager.HandleGuqinTouchMultiFinger()`
  - 品位触点：写入 `touchToFretHold` 与 `touchFretAnchor`（用于推拉）
  - 弦触点：只要某指命中弦，或者同一指从上一根弦滑到新弦，都会收集为一次 `pluckRay`（支持“拇指滑过多根弦依次发声”）。
  - 每帧先 `guqinController.SetLiveFretHold / SetBendAmount`，最后 `guqinController.HandlePluckWithLiveFret(ray)`。
- 琵琶：`InstrumentInputManager.HandlePipaTouchMultiFinger()`
  - 逻辑与古琴类似：一指按品（更新 `SetLiveFretHold / SetBendAmount`），另一指点弦或滑到新弦时立刻触发 `pipaController.HandlePluckWithLiveFret(ray)`，不再单独做“手机端扫弦判定”。

### 1.3 最终发声点

- `GuqinController` / `PipaController` 会对命中的 `InstrumentString` 调用：
  - 空弦：`ReleaseFret()` + `PluckString()`
  - 按品：`PressFret(fret)` + `PluckStringWithBend(bend)`
  - 泛音：`PluckStringHarmonic(multiplier)`
- `InstrumentString` 内部决定：
  - **优先**用 `fretSounds[fret]`（若 `preferCustomFretSounds=true` 且数组有资源）
  - 否则用 `openStringSound` + **音高变调**（`usePitchShifting=true`）
  - 再否则尝试从 `InstrumentAudioManager` 拉取（若场景存在）

## 2. 新增功能：常见 6 种扩展方式

下面每种方式都按“你应该改哪一层”来写，避免改错文件导致牵一发动全身。

### 2.1 新增一个“奏法/模式”（例如：古琴新增“揉弦”，琵琶新增“轮指”）

**推荐改动层级**：先改控制器（规则层），必要时再改 `InstrumentString`（能力层）。

- **步骤**
  - **在枚举里加新值**
    - 古琴：`GuqinTechnique`
    - 琵琶：`PipaTechnique`
  - **在控制器的 `HandlePluck(...)`（PC）里添加分支**
    - 古琴：`GuqinController.HandlePluck`
    - 琵琶：`PipaController.HandlePluck`
  - **如果是触控端“由手势自动推断奏法”**
    - 古琴：改 `GuqinController.HandlePluckWithLiveFret`
    - 琵琶：改 `PipaController.HandlePluckWithLiveFret`
  - **如果需要新能力（例如连续颤音/特殊衰减/特殊泛音）**
    - 再在 `InstrumentString` 新增公开方法，如 `StartTremolo(...)`、`SetDamping(...)` 等
    - 控制器只“调用能力”，不要把具体音频/震动细节塞回控制器里

- **配套：PC 按键切奏法**
  - 在 `InstrumentInputManager.Update()` 中添加/调整键位映射（参考现有 `guqinSanYinKey ... guqinTuiLaKey`、`pipa...Key`）

### 2.2 新增一个“新的交互手势”（非 UI，影响弹奏）

当前项目里，**手势系统只做 UI 点击**（捏合）。如果你要把手势用于弹奏，建议走两条路之一：

- **方案 A（快）**：把手势识别结果“伪装成触控/鼠标输入”，交给 `InstrumentInputManager`
  - 好处：所有乐器逻辑无需重写，只是多一种输入源
  - 做法：在 `InstrumentInputManager` 增加一个入口方法（例如 `InjectVirtualTouch(...)`），把屏幕坐标转换成 Ray，然后复用 `HandleGuqinTouchMultiFinger` / `HandlePipaTouchMultiFinger` 的逻辑分支
- **方案 B（干净）**：新增一个 `IInstrumentInputSource`（接口）并让 `InstrumentInputManager` 轮询多个输入源
  - 好处：结构清晰，后续扩展更多输入（手势、手柄、MIDI）更容易
  - 代价：改动面更大（建议多人协作前先统一接口）

> 如果你只是要“捏合=拨弦/按品”，先用方案 A；等需求稳定再重构成方案 B。

### 2.3 新增一个“新乐器”（例如二胡/筝）

**目标**：复用 `InstrumentString` 与 `InstrumentInputManager` 的大部分能力，只新增一个控制器。

- **建议的最小路径（推荐）**
  - 新建 `XxxController : MonoBehaviour`
    - 字段：`InstrumentString[] strings`、`int numberOfFrets`、`bool createFretCollidersPerString`、`Collider[][] fretCollidersPerString`
    - 方法：`HandlePluck(Ray)`（PC）、`HandleFretRecord(Ray)`（PC 可选）、`HandlePluckWithLiveFret(Ray)`（触控）、`GetFretFromHit(RaycastHit, out int si, out int fi)`
    - 直接参考 `GuqinController` / `PipaController` 的结构复制一份再删减
  - **在 `InstrumentInputManager` 增加第三种乐器选择**
    - 把 `activeInstrument` 从 0/1 扩成 0/1/2
    - 加 `public XxxController xxxController;`
    - 在 `SendPluckEvent / SendFretRecordEvent / HandleTouchInput` 分支里接入

- **不要做的事（容易越改越乱）**
  - 不要把三种乐器的规则塞进一个 Controller，用大量 `if (instrumentType==...)` 控制
  - 不要让 `InstrumentString` 知道“自己属于哪种乐器并自行决定奏法”（它只负责一根弦的能力）

### 2.4 新增/替换音色资源（音频）

你主要会改 `InstrumentString` 的 Inspector 配置，不一定需要改代码。

- **方式 1（最省资源）**：只配置 `openStringSound`，打开 `usePitchShifting=true`
  - 品位音由音高变调生成：第 \(n\) 品倍率 \(2^{(n+1)/12}\)
- **方式 2（音色更真实）**：给 `fretSounds[]` 配置逐品采样
  - 同时保持 `preferCustomFretSounds=true`，会优先用逐品采样
- **方式 3（集中管理）**：接入/完善 `InstrumentAudioManager`
  - `InstrumentString.TryGetAudioFromManager` 会按父级是否有 `GuqinController` / `PipaController` 来索引音频

### 2.5 调整“按品/品位碰撞体”的算法或位置

品位碰撞体有两套：

- **每弦独立品位（推荐）**：`createFretCollidersPerString=true`
  - 古琴：`GuqinController.CreateFretCollidersPerString`
  - 琵琶：`PipaController.CreateFretCollidersPerString`（位置用 `CalculateFretPosition` 对数曲线）
- **旧版品位（全弦共用一排）**：`CreateFretColliders`

如果你遇到“按品老是按到隔壁弦/不稳定”，优先调整：

- `CreateFretCollidersPerString` 里 `BoxCollider.size`（尤其是 x/z）
- 品位物体的 `localPosition` 计算方式（z 分布）

### 2.6 新增 UI 功能（按钮/面板/翻页），并支持手势点击

UI 交互走 `HandUIInteraction`，核心要求是：

- 场景里要有 `EventSystem`
- `Canvas` 上要有 `GraphicRaycaster`
- 目标控件需要可被射线命中（Image/Text 的 Raycast Target，或 Button 自身）

新增 UI 功能时建议：

- **按钮点击切场景**：给按钮绑定 `SceneLoader.LoadPlayScene()` / `LoadUIScene()`
- **按钮切换乐器**：给按钮绑定 `InstrumentInputManager.SetActiveInstrument(int)`
- **按钮切换奏法**：直接改对应 Controller 的 `currentTechnique`
  - 或者新增一个小脚本 `TechniqueButtonBinder`（更规范），但不是必须

如果你新增/运行时生成了按钮，需要调用：

- `HandUIInteraction.RefreshButtonList()`（让它重新收集按钮列表，备用“距离判定”才有效）

### 2.7 用手势打开/关闭指定面板（比耶 / 金属礼 / 竖拇指）

脚本：`Assets/Scripts/HandDecter/HandPanelGestureOpener.cs`

- **挂点**：手势交互场景中任意常驻物体（例如与 `HandInteractionManager` 同物体或子物体）。
- **必须配置**
  - `Target Panel`：拖入你要控制显示的面板根 `GameObject`（由你自选）。
  - `Data Collector`：指向 `HandLandmarkDataCollector`；若留空且场景里 `HandInteractionManager.autoSetup=true`，启动时会自动补上。
- **手势预设（`Gesture Preset`）**
  - **`RockHorns`（默认）**：食指 + 小指伸直，中指、无名指弯曲——**辨识度较高**，与「捏合」差异大。
  - **`PeaceVictory`**：经典比耶（食、中伸直；无名、小指弯曲）。
  - **`ThumbsUp`**：拇指伸直，其余四指弯曲。
- **与捏合共存**：勾选 `Reject While Pinching` 时，拇指–食指过近（视为捏合）不会触发本手势，减少和 `HandGestureDetector` 抢判。
- **防误触**：`Stable Frames Required`（连续满足多少帧才触发）、`Cooldown Seconds`（触发后冷却）。
- **行为**：`Toggle Panel` 为 true 时每次完整识别切换显示/隐藏；为 false 时仅负责「显示」面板。
- **可选**：`On Panel Shown` / `On Panel Hidden`（UnityEvent）可接音效、动画等。

## 3. 调整现有功能：按“改动目标”定位脚本

### 3.1 我想改“PC 鼠标怎么操作”

改 `InstrumentInputManager.HandleMouseInput()`：

- 左键拨弦：`SendPluckEvent`
- 右键记录按品：`SendFretRecordEvent`
- `Tab` 切乐器：`instrumentSwitchKey`
- 数字键切奏法：`Update()` 顶部的按键映射

### 3.2 我想改“手机多指逻辑（按品/拨弦/推拉/滑指跨弦触发拨弦）”

改 `InstrumentInputManager`：

- 古琴：`HandleGuqinTouchMultiFinger()`
  - 负责：多指按品、推拉、单指/多指在不同弦间滑动时的拨弦触发（同一指从上一根弦滑到新弦时会额外触发一次拨弦）。
- 琵琶：`HandlePipaTouchMultiFinger()`
  - 负责：与古琴类似的“按品 + 点弦/滑弦”逻辑，**当前手机端不再做自动扫弦判定**，扫弦只在 PC 端通过 `PipaTechnique.Strum` 演示。
- 推拉灵敏度：`bendPixelsPerSemitone`

### 3.3 我想改“按品规则/泛音点定义/推拉范围”

改 `GuqinController` 或 `PipaController`：

- 触控推断奏法：`HandlePluckWithLiveFret`
  - 当前实现把 **第 1 品（fretIndex==0）** 当作“泛音点”（倍率取 `HarmonicPitchMultipliers[0]`）
- 推拉范围：控制器里 `SetBendAmount` 已 Clamp 到 \([-2,2]\) 半音
- 持续发音实时变调：`Update()` 每帧对正在播放的弦调用 `UpdateSustainPitch(...)`

### 3.4 我想改“音色/音高算法/持续音行为”

改 `InstrumentString`：

- 音高变调公式：`PluckStringWithBend` 中 `pitchShift = Mathf.Pow(2f, (currentFret + 1) / 12f)`
- 推拉实时变调：
  - `UpdateSustainBend`（只改推拉）
  - `UpdateSustainPitch`（按品+推拉总倍率）
- 泛音：`PluckStringHarmonic(multiplier)`

### 3.5 我想改“弦的震动/变色/透明碰撞弦”

改 `InstrumentString`：

- 视觉目标：`visualStringObject`
- 是否让碰撞弦透明：`makeColliderInvisible` + `colliderAlpha`
- 震动幅度/时间：`vibrationDuration`、`VibrateEffect()` 中的 `0.03f` 幅度

### 3.6 我想改“手势点 UI 的判定/防误触”

改 `HandUIInteraction`：

- 捏合冷却：`interactionCooldown`
- 射线命中失败的备用距离判定：`detectionRadius` + `FindNearestButton`

改 `HandGestureDetector`：

- 捏合阈值：`pinchDistanceThreshold`

### 3.7 我想改「手势开面板」的灵敏度或手势类型

改 `HandPanelGestureOpener`：

- 换手势：`gesturePreset`（金属礼 / 比耶 / 竖拇指）
- 伸直/弯曲判定：`extendedRatio`、`curledRatio`（归一化 xy 下指尖与手腕距离相对 PIP 的比例）
- 稳定帧与冷却：`stableFramesRequired`、`cooldownSeconds`
- 与捏合冲突：`rejectWhilePinching`、`pinchRejectDistance`

## 4. 常见问题排查（90% 的“没反应”都在这里）

### 4.1 点弦没声音

- 检查弦物体是否有 `InstrumentString` + `Collider`（必须）
- 检查 `InstrumentString.openStringSound` 是否有赋值（或是否有 `InstrumentAudioManager`）
- 检查 `AudioSource` 是否存在（脚本会自动加，但仍建议看 Console 是否报错）
- 检查射线是否打到弦：
  - `InstrumentInputManager.showDebugRay=true`，Scene 视图看 `Debug.DrawRay`
  - Collider 是否在 `raycastLayerMask` 允许的层
- 检查是否点在 UI 上被拦截：
  - `InstrumentInputManager` 会用 `EventSystem.current.IsPointerOverGameObject(...)` 判断

### 4.2 按品不生效 / 总按到错弦

- 优先使用 `createFretCollidersPerString=true`
- 确认品位碰撞体是否带 `FretInfo`（推荐的 per-string 创建会自动挂）
- 调整品位碰撞体的 `BoxCollider.size` 与位置分布

### 4.3 推拉没效果

- 触控端推拉来自“按品指”的位移：
  - `InstrumentInputManager.bendPixelsPerSemitone` 过大 → 推拉不敏感
  - 需要确认触控时确实命中了品位（有写入 `touchFretAnchor`）
- 推拉只在“弦正在发音”时才会听得出来（控制器的 `Update()` 只对 `isPlaying` 的弦实时变调）

### 4.4 手势捏合点按钮没反应

- 场景里必须有 `EventSystem`
- Canvas 必须有 `GraphicRaycaster`
- Button 必须启用且可交互（`interactable`）
- 如果你运行时生成按钮，记得调用 `HandUIInteraction.RefreshButtonList()`

## 5. 团队协作建议（最少踩坑版）

- **一人负责一层**：
  - 输入层：`InstrumentInputManager`
  - 规则层：`GuqinController` / `PipaController`
  - 能力层：`InstrumentString`
  - UI 手势层：`HandGestureDetector` / `HandUIInteraction`
- **改动原则**：
  - “新增奏法/规则”优先改 Controller，不要直接在 `InstrumentString` 写大量分支
  - “改音色/视觉”优先改 `InstrumentString`，Controller 只调用公开方法
  - “改触控手势”优先改 `InstrumentInputManager`，不要在 Controller 里读 `Input.touches`
- **提交前自测**（最低限度）
  - PC：右键记录按品 + 左键拨弦是否正常；`Tab` 切乐器是否正常
  - 触控：一指按品 + 另一指拨弦是否正确；单指在多根弦间滑动是否每根都能依次发声

- **“点哪根弦 / 多指按品 / 滑指跨弦触发拨弦 / 推拉灵敏度”**：`Assets/Scripts/Instrument/InstrumentInputManager.cs`
- **“古琴奏法规则 / 泛音点 / 品位碰撞体生成 / 主音量”**：`Assets/Scripts/Instrument/GuqinController.cs`
- **“琵琶奏法规则 / PC 扫弦实现 / 品位分布曲线 / 主音量”**：`Assets/Scripts/Instrument/PipaController.cs`
- **“真正播放声音 / 音高变调 / 泛音倍率 / 推拉持续变音 / 每弦音量 / 视觉震动变色”**：`Assets/Scripts/Instrument/InstrumentString.cs`
- **“捏合检测（依赖 MediaPipe 手部关键点 + 摄像头权限）”**：`Assets/Scripts/HandDecter/HandGestureDetector.cs`
- **“捏合点 UI 按钮”**：`Assets/Scripts/HandDecter/HandUIInteraction.cs`
- **“特定手型打开/切换面板（金属礼/比耶/竖拇指）”**：`Assets/Scripts/HandDecter/HandPanelGestureOpener.cs`
- **“一键串联手势系统 / 进入手势场景时申请摄像头权限并开启 Runner / 离开场景前由 SceneLoader 关闭摄像头”**：`Assets/Scripts/HandDecter/HandInteractionManager.cs`
- **“手部关键点数据采集 / StartCamera/StopCamera 控制摄像头”**：`Assets/Scripts/HandDecter/HandLandmarkDataCollector.cs`
